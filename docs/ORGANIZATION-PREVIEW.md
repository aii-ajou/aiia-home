# 조직도 편집·검토·공개

기존 `centers` 콘텐츠는 **연구 분야**로 표시하며, 홈페이지의 분야별 소개에서 앞 번호를 제거합니다. 실제 운영 조직은 별도의 **조직도**에서 편집합니다. 기존 연구 분야 데이터 경로와 주소는 유지합니다.

## 운영자 편집 순서

1. CMS **조직도 → 조직 구성**에서 조직을 추가·삭제·정렬합니다. 종류는 상위기관(h), 협력기관(p), 위원회(c), 스탭·행정 부서(s), 일반·도메인 센터(d), 기업 브랜드 센터(i) 중 선택합니다.
2. 이름·관계·표시 여부를 입력합니다. 역할 설명·책임자 이름·사진·상세 페이지 주소는 선택 사항입니다. 책임자가 없으면 이름 자리도 표시하지 않습니다.
3. **Save**합니다. 그림에 영향을 주는 변경이면 자동 작업이 새 그림을 생성합니다. 생성이 끝난 뒤 CMS를 새로고침하고 **조직도 검토 그림**을 확인합니다.
4. **공개 승인 → 이 그림 확인 · 공개 승인**을 선택하고 다시 **Save**합니다. 배포가 완료되면 홈페이지에 반영됩니다. 승인 전에는 기존 공개 조직도가 유지됩니다.

승인은 표시된 그림의 버전에 연결됩니다. 그림 생성 후 이름 등을 다시 바꾸거나, 예전 그림의 승인 값이 편집 화면에 남아 있어도 새 그림이 자동 승인되지 않습니다. 새로고침 후 새 그림을 확인하고 승인해야 합니다.

그림 생성 대상은 연구원 이름·부제·책임자와, 표시되는 조직의 이름·관계·책임자·상세 링크·표시 여부 및 같은 관계 내 순서입니다. 숨긴 조직의 내용, 관계가 다른 조직끼리의 순서 교환, 역할 설명·사진·섹션 소개만 바꾸면 그림을 재생성하지 않습니다. 이미 생성한 동일 버전의 그림도 재사용합니다. 조직도 승인 대기 중에는 해당 조직의 설명과 사진도 기존 공개본을 유지하며, 다른 페이지의 편집은 계속 반영됩니다.

## 화면과 연결

관계는 AIIA를 기준으로 합니다. 상위기관은 위에서 아래로 연결하며, 협력기관은 좌우, 행정 조직과 위원회는 중간 양쪽, 센터는 하단에 표시합니다. 임의 깊이의 하위 조직 편집은 이번 범위에 포함하지 않습니다.

홈페이지는 승인된 데이터로 정적 HTML 조직 상자와 SVG 연결선을 표시합니다. 방문 때 그림을 생성하지 않습니다. 창 너비에 맞춰 원본의 **80~100%**로 표시하며 최소 크기보다 좁으면 가로 스크롤이 생깁니다. 큰 창에서도 원본보다 확대하지 않습니다. 일반·도메인 센터의 종류명은 표시하지 않습니다.

상세 페이지 주소가 있으면 조직명을 눌러 이동합니다. 별도 페이지의 자동 생성 기능은 포함하지 않습니다. 기존 연구기획 TF 기능·파트너십 설명은 접어서 볼 수 있는 보충 설명으로 유지합니다. 예전 `leadership`, `center_groups` 데이터는 보존하지만 새 조직도에서는 사용하지 않습니다.

초기 공개본은 사용자 확인을 받은 총장·인공지능대학원·연구기획 TF·운영위원회와 가상 센터 5개입니다. 책임자·사진·링크는 비워 두고 역할 설명을 작성했습니다.

## 구현과 운영

- 비공개 콘텐츠 저장소의 `content/organization.json`은 CMS 편집본, `organization-review/published.json`은 마지막 승인본입니다. `state.json`에는 그림 입력의 SHA-256 버전을 기록합니다.
- 그림은 `organization-review/previews/<hash>.png`에 보관하고 CMS의 읽기 전용 본문 필드에서 확인합니다. 미리보기 이미지와 승인 제어 필드는 공개 빌드에 포함하지 않습니다.
- 콘텐츠 저장 작업은 최신 코드 저장소의 `scripts/review-organization.mjs`로 변경 여부를 비교합니다. 새 그림이 필요할 때만 Chromium과 한글 폰트를 설치하고 `scripts/render-organization-preview.mjs`로 실제 홈페이지의 조직도를 캡처합니다.
- 그림·승인 선택지·공개본은 하나의 커밋으로 저장합니다. 생성 중 다른 편집이 저장되면 오래된 결과의 push는 거부되며, 다음 실행이 최신 내용을 처리합니다.
- 공개 빌드는 반드시 승인본을 사용합니다. 승인본이 없거나 기록된 버전과 다르면 실패합니다. 검토 상태를 아직 설치하지 않은 옛 콘텐츠와 샘플은 이전 방식과 호환됩니다.
- 설명·사진만 바뀌면 승인본을 갱신하되 그림은 재사용합니다. 미디어 정리는 편집본과 승인본 모두에서 사진 참조를 확인하여, 승인 대기 때문에 현재 공개 사진이 보관함으로 이동하지 않도록 합니다.
- 개발자 설치 파일: `cms/pages.yml` → `.pages.yml`, `cms/publish-site.yml` → `.github/workflows/publish-site.yml`, `cms/reconcile-media.mjs` → `scripts/reconcile-media.mjs`. 승인 선택지는 작업이 동적으로 갱신합니다.
- 최초 설치 시 사용자가 확인한 초기 데이터에 대해서만 `apply --bootstrap-approved --hash HASH --image PNG`로 승인본을 만듭니다. 이후 운영에는 초기화 옵션을 사용하지 않습니다. 레이아웃 코드 변경으로 그림 형식이 바뀌면 `chartData`의 버전을 올려 새 미리보기를 생성합니다.

개발용 미리보기 빌드에는 `AIIA_ORGANIZATION_PREVIEW=true`를 사용합니다. 운영 배포와 함께 이 옵션을 사용하면 빌드를 거부합니다.

```bash
AIIA_ORGANIZATION_PREVIEW=true AIIA_CONTENT_SOURCE=.aiia/organization-preview npm run build
node scripts/render-organization-preview.mjs /tmp/organization-preview.png
```
